# 编写 Skill 文档

## 触发条件

当完成了一个可复用的操作流程，或者发现某类任务需要固定流程时，应该创建对应的 skill 文档。

典型场景：
- 多次执行类似操作，发现步骤固定且容易出错
- 完成了一个有明确输入输出的标准化流程
- 某个操作涉及多个文件、多个步骤，需要记录完整流程

## 输入格式

编写 skill 前需要明确：
1. **Skill 名称**：kebab-case，如 `add-system-settings`
2. **触发场景**：用户说什么话时应该使用这个 skill
3. **输入要求**：用户需要提供哪些信息
4. **输出内容**：执行完成后会产生什么结果

## Skill 文档结构

### 文件位置

```
.claude/skills/
└── <skill-name>/
    └── SKILL.md
```

例如：`.claude/skills/add-system-settings/SKILL.md`

### 标准格式

```markdown
---
name: skill-name-in-kebab-case
description: 一句话描述这个 skill 的用途，当用户提到 XXX 时使用。
---

# Skill 的中文标题

## 触发条件

明确说明什么情况下应该使用这个 skill。

可以列举具体的用户输入示例：
- "帮我添加系统设置"
- "新增一个 XXX 功能"
- "我要实现 YYY"

## 输入格式

用户需要提供哪些信息？每项信息的格式要求是什么？

示例：
1. 配置项的 key（点分命名法，如 `mail.smtp.host`）
2. 值类型（STRING / NUMBER / BOOLEAN 等）
3. 默认值

## 前提信息

执行这个 skill 需要了解的背景知识：
- 相关的类、接口、常量定义
- 项目中已有的约定和规范
- 相关文件的位置和作用

这部分可以包含：
- 类结构说明
- 表格对比
- 代码示例

## 执行步骤

### 第 0 步：前置检查（如果需要）

执行前必须确认的事项，避免做无用功。

### 第 1 步：后端/前端操作标题

**文件：** `明确的文件路径`

**操作：** 具体要做什么

**示例：**（可选，提供代码示例）
```kotlin
// 代码示例
```

**关键注意：**（可选，特别需要注意的点）
- 注意事项 1
- 注意事项 2

### 第 2 步：...

重复上述格式。

### 最后一步：验证

**后端：**
```bash
./mvnw clean compile -DskipTests
```

**前端：**
```bash
cd web && npx tsc --noEmit
```

**必须确认：**
- ✅ 编译通过
- ✅ 功能正常
- ✅ 符合规范

## 输出格式

执行完成后，向用户汇报：
1. 修改了哪些文件
2. 添加了哪些内容
3. 需要用户自行验证的部分（如果有）

## 编写 Skill 的执行步骤

### 第 1 步：创建 Skill 目录和文件

**操作：**
```bash
mkdir -p .claude/skills/<skill-name>
touch .claude/skills/<skill-name>/SKILL.md
```

### 第 2 步：编写 Frontmatter

**必须包含：**
```yaml
---
name: skill-name-in-kebab-case
description: 一句话描述，说明何时使用这个 skill。
---
```

**关键注意：**
- `name` 必须与目录名一致
- `description` 应该包含触发关键词（如"当用户提到添加系统设置时使用"）
- frontmatter 后必须有一个空行

### 第 3 步：编写触发条件

**必须明确：**
- 什么场景下使用这个 skill
- 用户可能的输入示例
- 与其他 skills 的区别（如果容易混淆）

**示例：**
```markdown
## 触发条件

当用户要求添加系统级的配置项时使用。

> 添加**租户设置项**请改用 `add-tenant-settings` skill，两者所在模块不同。
```

### 第 4 步：编写输入格式

**必须说明：**
- 用户需要提供哪些信息
- 每项信息的格式要求
- 哪些信息是必填，哪些是可选

### 第 5 步：编写前提信息

**包含：**
- 相关的类、接口、常量定义
- 文件位置
- 项目约定
- 技术背景

**使用表格、代码示例增强可读性。**

### 第 6 步：编写执行步骤

**关键原则：**
1. **步骤编号从 0 或 1 开始**
2. **每个步骤包含：**
   - 小标题（操作内容）
   - 文件路径（如果涉及文件修改）
   - 具体操作说明
   - 代码示例（如果需要）
   - 关键注意事项
3. **区分强制步骤和可选步骤**
   - 强制步骤：必须执行
   - 可选步骤：按需执行，明确标注"可选"
4. **最后一步必须是验证**
   - 编译检查
   - 功能测试
   - 确认清单

**示例格式：**
```markdown
### 第 1 步：后端添加常量定义

**文件：** `crystal-system/.../SystemSettingsConstants.kt`

**操作：** 在对应 nested object 中添加 `val` 声明

**示例：**
\```kotlin
object Basic {
    val NEW_SETTING = SettingsItemDeclaration(
        key = "basic.newSetting",
        valueType = SettingsItemValueType.STRING,
        defaultValue = "default",
    )
}
\```

**关键注意：**
- `key` 必须唯一，先检查是否重复
- `defaultValue` 必须是字符串类型
```

### 第 7 步：编写输出格式（可选）

**说明：** 执行完成后向用户汇报什么内容

### 第 8 步：添加关联 Skills（可选）

**说明：** 如果依赖或关联其他 skills，明确列出

### 第 9 步：添加完整示例（推荐）

**说明：** 提供一个端到端的实际案例，展示整个流程

## Skill 文档的关键原则

### 1. 明确性原则
- 每个步骤都要说清楚"做什么"、"在哪里做"、"怎么做"
- 避免模糊表述如"然后更新相关文件"
- 必须给出具体的文件路径

### 2. 完整性原则
- 涵盖从输入到输出的完整流程
- 包含验证步骤
- 说明可能的错误和解决方案

### 3. 可读性原则
- 使用标题、列表、表格、代码块增强结构
- 关键信息加粗或使用引用块
- 复杂概念提供代码示例

### 4. 维护性原则
- 当项目结构变化时及时更新 skill
- 发现 skill 有错误或遗漏时立即修正
- 定期回顾是否有新的步骤需要补充

### 5. 防错性原则
- **必须**标注哪些步骤是强制的
- **禁止**标注哪些操作是禁止的
- **注意**标注容易出错的地方
- 提供检查清单避免遗漏

## 常见错误和避免方法

### 错误 1：步骤不完整
**问题：** 遗漏关键步骤，导致执行后功能不完整

**避免：**
- 亲自执行一遍流程，记录每个操作
- 列出所有涉及的文件
- 包含验证步骤

### 错误 2：文件路径不明确
**问题：** 只说"在某个文件中"，但没有给出完整路径

**避免：**
- 总是给出相对于项目根目录的完整路径
- 说明文件所在的模块

### 错误 3：缺少示例
**问题：** 只有文字描述，没有代码示例

**避免：**
- 复杂操作必须提供代码示例
- 示例要完整可用，不要省略关键部分

### 错误 4：没有区分强制和可选
**问题：** 所有步骤看起来都一样重要

**避免：**
- 明确标注"必须"、"可选"
- 可选步骤说明在什么情况下需要执行

### 错误 5：没有验证步骤
**问题：** 执行完不知道是否成功

**避免：**
- 最后一步必须是验证
- 提供具体的验证命令
- 列出验证清单

## 输出格式

编写完 skill 后，向用户确认：

1. **Skill 名称：** `<skill-name>`
2. **文件位置：** `.claude/skills/<skill-name>/SKILL.md`
3. **触发场景：** （复述 description）
4. **涵盖步骤：** （列出主要步骤）
5. **关联 Skills：** （如果有）

并询问用户是否需要调整或补充。

## 示例：创建 add-system-settings skill

### 输入
用户说："帮我总结一个添加系统设置的 skill"

### 分析
- Skill 名称：`add-system-settings`
- 触发场景：用户要添加系统级配置项
- 涉及文件：SystemSettingsConstants.kt、SystemSettings.kt、SystemSettingsServiceImpl.kt、i18n 文件等
- 主要步骤：后端添加常量 → 更新数据类 → 实现读写方法 → 前端添加翻译

### 创建 skill

1. 创建目录：`.claude/skills/add-system-settings/`
2. 创建文件：`SKILL.md`
3. 编写 frontmatter：
```yaml
---
name: add-system-settings
description: 为系统添加设置项，当用户提到添加某项系统配置时使用。
---
```
4. 编写各个章节：触发条件、输入格式、前提信息、执行步骤、输出格式
5. 添加代码示例和表格
6. 包含验证步骤

### 输出
创建了 skill 文档：`.claude/skills/add-system-settings/SKILL.md`

主要章节：
- 触发条件：明确了与 add-tenant-settings 的区别
- 输入格式：说明需要 key、值类型、默认值
- 前提信息：介绍 SettingsItemDeclaration 结构、支持的值类型
- 执行步骤：后端 6 个步骤 + 前端 5 个步骤
- 输出格式：列出新增的配置项和翻译
